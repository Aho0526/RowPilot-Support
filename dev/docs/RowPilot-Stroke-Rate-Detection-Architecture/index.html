RowPilot Stroke Rate Detection Architecture

RowPilot measures stroke rate (SPM — Strokes Per Minute) using the iPhone's built-in accelerometer, requiring no external hardware. The algorithm is inspired by peer-reviewed rowing biomechanics research and established commercial implementations, and is designed to work regardless of how the phone is mounted on the boat.

1. Physical Principle

Boat Acceleration Pattern

During a rowing stroke cycle, the boat's longitudinal (forward) acceleration follows a characteristic waveform:

Stroke PhaseAcceleration Characteristics
Drive (catch → finish)Positive — Blade in water, boat accelerates forward.
Recovery (finish → catch)Negative — Rower's body moves forward towards stern, boat decelerates.

The catch — the moment the blade enters the water and drive begins — corresponds to the transition from a negative trough to a positive phase (negative-to-positive zero-crossing).

References

  • CrewNerd (performancephones.com): Monitors characteristic patterns in horizontal boat acceleration to detect the catch.
  • NK SpeedCoach: Identifies the "negative peak (minimum)" at the recovery-to-drive transition.
  • Academic research (Rowing in Motion / RUG): Uses zero-crossings after low-pass filtering to classify catch and finish.
  • Open Rowing Monitor (github.com/laberning/openrowingmonitor): Manages drive/recovery phases via a finite state machine.

2. Sensor Configuration

Device Motion (CMMotionManager)

RowPilot uses Apple's CMMotionManager with device motion updates (gravity-corrected acceleration) rather than raw accelerometer data.

  • Sampling Rate: 50 Hz (20ms interval)
  • Data Type: userAcceleration — linear acceleration with 1G gravity mathematically removed.

Dynamic Axis Selection

Since the phone can be mounted in any orientation (horizontal, vertical, or angled on a foot stretcher), RowPilot does not assume a fixed axis. Instead, it continuously tracks the exponential moving average (EMA) of signal amplitude on all three axes and dynamically selects the most active one.

α = 0.01  (time constant ≈ 2 seconds at 50 Hz)
varianceX = varianceX × (1 − α) + |accel.x| × α
varianceY = varianceY × (1 − α) + |accel.y| × α
varianceZ = varianceZ × (1 − α) + |accel.z| × α

activeAxis = argmax(varianceX, varianceY, varianceZ)

This makes the detection robust to arbitrary phone mounting directions — landscape, portrait, flat, or tilted.

3. Signal Processing

2nd-Order Butterworth Low-Pass Filter

Raw accelerometer data contains high-frequency noise from water chop, hull vibration, and rower seat movement. A 2nd-order Butterworth filter suppresses noise above 3 Hz while preserving the stroke-frequency signal (typical rowing: 0.3–1.5 Hz / 18–90 SPM).

4. Catch Detection — Finite State Machine

Overview

The filtered signal is processed by a 3-state finite state machine that tracks the stroke phase and identifies the catch event with sub-sample precision.

[*] ──► Idle
Idle ──────────────► InTrough   (when polarizedSignal < −threshold)
Idle ──────────────► InDrive    (when polarizedSignal > +threshold)
InTrough ──────────► InDrive    (zero-crossing −→+ : REGISTER CATCH)
InTrough ──────────► Idle       (signal returns within threshold without crossing)
InDrive ───────────► Idle       (signal < zeroCrossHysteresis)

States

StateDescription
IdleSignal within threshold; no active stroke phase.
InTroughSignal has entered the negative trough; tracking the absolute minimum point.
InDriveSignal is in the positive drive phase.

Polarity Auto-Detection

The algorithm automatically determines whether the catch corresponds to a positive or negative acceleration peak depending on how the phone is mounted. The first significant threshold crossing establishes the polarity for the session.

ParameterValueDescription
Catch Threshold0.06 GMinimum acceleration magnitude required to enter a trough.

5. SPM Calculation

Catch Timestamp — Sub-Sample Precision

The catch is registered at the timestamp of the trough minimum (the most negative point), not the zero-crossing. This provides more accurate timing by anchoring directly to the physical event.

Median of Recent Intervals

SPM is computed from the median of the 3 most recent inter-catch intervals. The median is chosen over the mean because it is exceptionally robust to outlier intervals caused by missed strokes or false catches.

intervals = [t1→t2, t2→t3, t3→t4]    (from last 4 catch timestamps)
medianInterval = median(intervals)
rawSPM = 60.0 / medianInterval

Valid interval range: 0.5 s – 6.0 s (equivalent to 10–120 SPM).

Exponential Moving Average (EMA) Smoothing

To prevent the displayed SPM from flickering while preserving fast feedback:

smoothedSPM = 0.6 × rawSPM + 0.4 × previousSPM

The weight of 0.6 on the current value ensures fast response to genuine rate changes while dampening transient sensor jitter.

Dynamic Debounce

To prevent double-counting within a single stroke, a minimum inter-catch interval is enforced. The debounce window adapts dynamically to the current SPM:

strokePeriod = 60.0 / currentSPM
debounce = clamp(strokePeriod × 0.45, min: 0.4s, max: 2.0s)

This allows the algorithm to accurately track high stroke rates (e.g., race starts at 40+ SPM) without false rejections.
