RowPilot PM5 Communication Architecture v4.1

In v4.1, the communication specification has been updated and refined to match the actual implementation. The traditional "fixed-time waiting" method is eliminated in favor of a State-Synchronized Architecture that proceeds while monitoring the actual state (Machine Status) of the PM5. Each PM5 is managed as an independent state machine.

Communication Layer

Extended CSAFE Frame

Prioritizing stability when multiple PM5s are connected, all communication is standardized to the Extended CSAFE Frame.

Structure

F0 [Destination] [Source] [Payload] [Checksum] F2
FieldValue / Rule
Destination Address0xFD — Default secondary address
Source Address0x00 — Host
ChecksumXOR of payload bytes only (excludes Destination/Source)
Byte Stuffing ScopeEntire packet between 0xF0 start flag and 0xF2 stop flag
Stuffed Bytes0xF0 ~ 0xF3 — escaped via standard CSAFE method

Transmission Architecture

CSAFECommandQueue

To prevent instability in BLE communication, all transmissions are managed by a dedicated queue using Swift Actors to guarantee order per device.

Global Write Limiter

To prevent congestion in the CoreBluetooth internal queue, concurrent BLE writes are globally limited.

maxConcurrentWrites = 3

Write Timeout

Individual write operations have a dedicated timeout duration. If a write does not complete within this window, the operation fails and the device state is updated.

writeTimeout = 2.0s

Inter-frame Delay

To comply with the CSAFE specification and ensure processing time on the PM5:

Gap TypeDurationApplied When
Minimum Inter-frame Gap50msAfter each frame transmission
Multi-frame Transmission Delay150msBetween configuration chunks (e.g., Variable Interval setup)

Parallel / Sequential Hybrid

Within Device: Sequential — guarantees transmission order to each PM5.
Between Devices: Parallel — controls multiple PM5s concurrently.

v4.1 Workflow

Phase 1 — TERMINATE

Send a forced reset to all PM5s.

  • CSAFE command: CSAFE_PM_SET_SCREENSTATE with ScreenType = WORKOUT (0x01) and ScreenValue = TERMINATE (0x02).
  • Purpose: End any current workout and initialize PM5 internal state.
The v4.1 workflow phases are designed to transition the PM5 through state-machine stages rather than relying on fixed sleep timers. This makes the protocol more robust in variable BLE latency environments.
