### 18. 多重連鎖移動の強固なエンジン刷新 & ステージ19の完全解法対応
- **背景**:
  - これまで「クリア不可」と見なされていたステージ19において、ユーザーによって美しい正解配置が発見された。
  - しかし従来の移動ロジックでは：
    1. 移動順序が方向決め打ち（`rightMoves` が常に最初）だったため、右向きブロック（紫マス）が先に動いてまだ退避していない上向きブロックに衝突して手前で停止していた。
    2. 上向きブロックが先に動いた場合でも、右向きブロックが通過する際に上向き矢印タイルを踏んでしまい、途中で上に曲がって上のブロックに激突して停止していた。
- **改善後アーキテクチャ**:
  1. **トポロジカル依存関係解析＋局所 `step` 先行退避**:
     - 局所退避である `step`（緑：1マス移動）を最優先で処理し、その内部でブロック同士の進路干渉をトポロジカルソートで自動解決。通路を塞ぐブロックが確実に先に退避してスペースを空ける。
     - その後、大域移動である `dash`（水色：端まで滑る）を実行することで、空いた通路を一気に駆け抜ける物理的・論理的に自然な挙動を実現。
  2. **初期ブロック発進マスの「通過マス化（`vacatedGimmickCells`）」**:
     - 初期配置のブロックが別の方向へ発進したギミックマスは、そのラウンドでは「発進済みの床」として扱い、後から通り抜けるダッシュブロックを誤って曲げないよう安全弁を構築。
     - 一方で、ステージ1や12のように「元々ブロックが置かれていなかった空のギミックタイル」に着地した場合は正規の連鎖として正しく発動。
  3. **全19ステージ 100% PASS 検証完了**:
     - ステージ1〜18の全既存解法および新解法ステージ19のすべてにおいて、1つの例外もなく完全クリア動作を確認。

### 21. ライブエディタの全面強化（コードマップ・リアルタイム構文診断・安全な雛形挿入）
- **背景・要望**:
  - 従来のライブエディタでは「雛形コードを挿入」ボタンを押すと `Unexpected token '{'` の構文エラーが発生し、初心者には原因が分からなかった。

     - 挿入された新規ステージの先頭行へ自動スクロールし、ハイライト表示。
  2. **リアルタイム構文診断エンジン（Linter）**:
     - **全角記号検出**: 初心者が最も陥りやすい全角スペース（`\u3000`）、全角コロン（`：`）、全角カンマ（`，`、`、`）、全角括弧、全角クォート等を即座に検知。
       - **文字列・コメント内の完全除外（誤検出防止）**: 文字列リテラル（`'...'`, `"..."`, `` `...` ``）内の日本語テキスト（例: `text: '赤の斜線：配置不可'`）やアイコン文字（例: `icon: '／'`）、およびコメント行（`//`, `/* */`）内部に含まれる全角記号は正常な日本語表記として完全にスキップ。プログラミングの構文部分（文字列の外側）に混入した全角記号のみをピンポイントで検出するよう高精度化。
     - **構文エラー行のピンポイント特定**: `findSyntaxErrorLine` と `getAutoCloseBrackets` により、1行ずつコードを構文解析して正確なエラー発生行を特定。カンマ抜けによる次行エラーも直前行へ補正。
     - **親切な日本語ヒント生成**:
       - `Unexpected token '{'`: 「波括弧「 { 」の位置が不正か、直前の行末尾にカンマ「 , 」が抜けています」
       - `Unexpected identifier`: 「カンマ「 , 」が抜けているか、文字列が「 " " 」で囲まれていません」
       - `Unexpected string`: 「文字列の位置が不正です（前の行の末尾にカンマ「 , 」が抜けていないか確認してください）」
       - `Unexpected end of input`: 「コードが途中で終わっています（括弧やクォートが閉じられていません）」
  3. **リアルタイム診断UI**:
     - エディタ上部に診断バナー（エラー内容・修正ヒント・「該当行へ移動」ボタン）を新設。
     - 行番号カラムのエラー行・警告行を赤・橙ハイライト（`.line-num.error`）。
     - ステータスバーに診断ドット（緑/赤/橙）とステータス表示を統合。
  4. **高精細ミニマップ（VS Code 風コードマップ）**:
     - 高DPI（retina）対応の Canvas レンダリング。
     - トークナイザーによるシンタックスカラー描画（コメント、文字列、予約語、数値、プロパティ名）。
     - エラー行・警告行の赤・橙背景ハイライト帯（`rgba(239, 68, 68, 0.45)`）。
     - ミニマップ右端のガターに、ファイル全体のエラー俯瞰マーカーを常時描画。

## 主な変更点 & バグ修正まとめ

### 1. キャンバスの縦横比潰れ（アスペクト比歪み）の完全修正
- **問題点**:
  - 画面高が低い端末（タブレット等）で `max-height` を適用した際、幅が強制的に引き伸ばされてグリッドやキャラクターが横長にペッタンコに潰れていた。

### 2. 右端オレンジ壁の貫通バグの修正
- **問題点**:
  - ステージ4にて U, V, G, L などに配置してキャラクターが右端（col 4 の段差上）に到達した際、壁衝突の座標計算が `curX = COLS (5.0)` まで歩かせていたため、オレンジ色の壁の境界線を越えて壁の中にめり込み・突き抜けてしまっていた。
- **改善後**:
  - スティックマンの身体幅（右端まで約10px）を考慮し、右壁衝突位置を `wallHitX = COLS - 0.65`（約4.35、col 4 の右寄りで鼻先が壁境界にピタッと触れる位置）に修正。
  - 壁を貫通することなく、**境界線手前でコツンと衝突してスタックし、即座にミス判定→リスポーン**するようになりました。

### 3. 地面歩行の維持 & 壁・障害物スタック時の「即時アウト」判定
