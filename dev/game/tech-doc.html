2. コードに出てくる「変な記号」の意味をスッキリ解剖！

プログラムのファイルを開くと、{ } や [ ]、: や , など普段あまり使わない記号がたくさん出てきます。 でも実は、意味はたったこれだけです！

{ }
波かっこ（中かっこ）＝「1枚の情報カード」
1つのモノの情報をひとまとめにする袋です。
例: { col: 1, row: 3 } は「横が1番目、縦が3番目のマスだよ」という1枚のマスカードです。
[ ]
角かっこ（大かっこ）＝「リスト・一覧表」
複数のカードを順番に並べた箱（配列）です。
例: [ { col: 1 }, { col: 2 } ] は「カードが2枚入ったリスト」です。
:
コロン ＝「〜は」
項目名と中身を繋ぎます。
例: maxBlocks: 5 は「最大ブロック数は 5 だよ」という意味です。
,
カンマ ＝「〜と（区切り）」
情報と情報を区切る句読点です。
例: 「リンゴ, みかん, バナナ」と同じ！ 最後の1個以外には必ずつけます。忘れるとコンピュータが「どこで区切ればいいの？」と迷子になってエラーになります。

4. 実物のコードを1行ずつ読んでみよう

記号の意味が分かったら、実際の stages.js（ステージ1）を読んでみます。
左が実際のコード、右が日本語での意味です。「何を書いているか」が読めれば、書き換えもできます。

コード意味
{ステージ1枚分の情報カードを開く
id: 1,ステージ番号は 1
title: 'ステージ 1',タイトルは「ステージ 1」（文字は ' ' で囲む）
maxBlocks: 7,置けるブロックは最大 7 個
startRow: 3,スタートの土管は、上から数えて 3 の高さ（0 が一番上）
goalRow: 1,ゴールは、上から数えて 1 の高さ
forbidden: [ … ],置けないマスのリスト。中に { col: 3, row: 0 } のようなマスカードを並べる
gimmicks: [ … ],矢印マスのリスト

コメント（//）について

各項目の詳しい書き方は「リファレンス: パラメータ辞書」にあります。今は全部覚えなくて大丈夫です。

5. 「solution」とは？

solution ＝「正解の置き方」

英語の solution は「解答・答え」という意味です。
パズルなのに、なぜコードに答えが書いてあるのか、疑問に思うかもしれません。理由は2つあります。

  1. 答え合わせ機能のため
    ゲーム画面右上の電球ボタン（または . キー）を押すと、solution に書かれたマスがオレンジ色の枠で表示されます。
  2. 今の置き方が合っているか判定するため
    答え合わせ中は、置いたブロックが solution とどれだけ一致しているかを「3/5 正解」のように表示し、全部合えば「正解の配置と一致しています」と表示します。
自分でステージを作るとき
solution は、作者が先に自分で解いて、クリアできたときのブロック位置を書き写して作ります。
空の solution: [] でもゲーム自体は遊べますが、答え合わせは何も表示されません。

6. ライブエディタの見方

「ライブエディタを開く」を押すと、画面が左右に分かれます。右側の構成は次のとおりです。

場所役割
右上本物のゲーム画面。そのまま遊べます。
右下のタブ（stages.js など）見たいファイルを切り替えます。最初は stages.js だけ触れば十分です。
赤いバー書き間違いがあると、原因と直し方が表示されます。「該当行へ移動」で、その行に飛べます。
行番号の赤色エラーのある行です。
右端の縦長の図（コードマップ）ファイル全体の縮小図です。赤い部分がエラーの位置で、クリックするとそこへ移動します。
「雛形コードを挿入」新しいステージの見本を末尾に追加します。
「変更をゲームに反映」書いた内容を、右上のゲームに反映します。
壊しても大丈夫です
エディタで書き換えた内容は、ファイルには保存されません。ゲームに反映されるのは今開いているページの中だけで、ページを再読み込みすれば元に戻ります。思い切って試してください。

7. やってみよう: 3分でできる改造チャレンジ

実際に1か所だけ書き換えて、ゲームが変わるのを確認します。
ここで書き換えるのはステージ1の maxBlocks（置けるブロックの数）です。

STEP 1
ライブエディタを開き、ステージ1の該当行へ移動する

下のボタンを押すと、画面が分かれ、maxBlocks: 7, の行にジャンプします。

STEP 2
数字の「7」を「10」に書き換える

ハイライトされた行の 7 を、半角の 10 に書き換えます。数字・カンマは半角で入力してください。

// 変更前
maxBlocks: 7,

// 変更後
maxBlocks: 10,
STEP 3
「変更をゲームに反映」を押す

書き換えた行にカーソルがある状態で、緑の「変更をゲームに反映」を押します。
右上のゲームがステージ1になり、画面右の「BLOCKS」が 0 / 10 に変わっていれば成功です。
赤いバーが出た場合は、書き方に間違いがあります。内容を読んで直してください。

もう少し試したい人へ

  • forbidden の中の数字を変えて、赤い斜線のマスを動かす
  • startRow を 0〜4 の別の数字にして、土管の高さを変える

stages.js 辞書

ステージの設計図（stages.js）に書く項目を、1つずつ説明する辞書です。
初めての方は、まず「1. 辞書の読み方」を読んでから、「2. 最低限必要な項目」の順に進んでください。

1. 辞書の読み方 2. 最低限必要な項目 3. 盤面を作る項目 4. ギミック（矢印） 5. 仕上げの項目 6. よくあるエラー

1. 辞書の読み方

用語

用語意味stages.js での例
プロパティ「名前: 値」の1組。設定項目のこと。maxBlocks: 7
数値数字。引用符で囲みません。startRow: 3
文字列文字。必ず ' か " で囲みます。title: 'ステージ 1'
真偽値true（はい）か false（いいえ）。囲みません。purpleBorder: true
オブジェクト{ } で囲んだプロパティのまとまり。カード1枚のイメージ。{ col: 3, row: 0 }
配列[ ] で囲んだ、複数のものを並べたリスト。要素は , で区切ります。forbidden: [ {…}, {…} ]

書き方の5つのルール

  1. 名前と値の間は半角の :（コロン）。例: id: 1
  2. 項目と項目の間は半角の ,（カンマ）。最後の1つだけは付けなくてOK（付けてもエラーにはなりません）。
  3. { } と [ ] は、開いたら必ず閉じる。
  4. 文字列は ' ' で囲む。閉じ忘れに注意。
  5. 記号とスペースはすべて半角。全角のコロンやスペースが混ざると動きません。ただし ' ' の中の日本語はそのままで大丈夫です。

バッジの意味

必須 書かないとゲームが動かない、またはエラーになる項目
任意 書かなくても動く項目（省略時の動きを各項目に書いています）

マスの位置（col と row）

col は左から数えた列、row は上から数えた行です。どちらも 0 から始まり、0〜4 を使います。
下の図は { col: 3, row: 1 } の位置です（青いマス）。

2. 最低限必要な項目

ステージ1つ分は、次の7項目で動きます。まずはこれだけ覚えれば大丈夫です。

最小のステージ（コピーして使えます）
{
    id: 20,
    title: 'ステージ 20',
    subtitle: 'はじめての自作',
    maxBlocks: 3,
    startRow: 3,
    goalRow: 1,
    forbidden: [],
    gimmicks: [],
    solution: [],
    legends: []
}
配列の項目は、使わないときも []（空の配列）と書いてください。項目ごと消すとゲームが止まることがあります。
id 必須 数値
一言で: ステージの番号です。
値: 1 から順番に、他と重複しない整数。20番目なら id: 20。
よくある間違い: 他のステージと同じ番号にすると、どちらか分からなくなります。
title 必須 文字列
一言で: 画面上のステージ名です。
値: ' で囲んだ好きな文字。例: title: 'ステージ 20'
よくある間違い: 引用符を閉じ忘れると、その先のコードが全部文字列扱いになります。
subtitle 必須 文字列
一言で: ステージ名の下に出る一言メモです。
値: 文字列。ステージのコンセプトを書くのがおすすめです。
maxBlocks 必須 数値
一言で: プレイヤーが置けるブロックの数です。難易度を決める一番大事な数字です。
値: 整数。既存の19ステージでは 5〜7 です。目安もこの範囲です。
ポイント: 正解（solution）の数より小さくするとクリアできません。同じか、少し多くします。
startRow 必須 数値 0〜4
一言で: スタート（緑の土管）の高さです。
値: 0 が一番上、4 が一番下。startRow: 3 なら下から2段目です。
goalRow 必須 数値 0〜4
一言で: ゴールの高さです。右端にあります。
値: 0〜4。startRow と同じ数え方です。

3. 盤面を作る項目

forbidden 必須 配列（マスの位置のリスト）
一言で: ブロックを置けないマスのリストです。画面では赤い斜線で表示されます。
値: { col: 列, row: 行 } を並べます。ない場合は forbidden: []。
forbidden: [
    { col: 1, row: 0 },
    { col: 3, row: 2 }
]
上のコードの見え方。赤いマスが置けない場所です。
よくある間違い: 最後の要素以外にカンマがないと Unexpected token のエラーになります。
hasCeiling 任意 真偽値 true / false
一言で: 画面の一番上に天井を付けるかどうかです。
値: true で天井あり。書かなければ false（天井なし）です。
天井があると、ジャンプで上にはみ出したときに頭をぶつけて失敗になります。

4. ギミック（矢印マス）

gimmicks は、矢印などの特別なマスのリストです。1つのマスは { } 1個で表し、使える項目は次の6つです。

項目必要？意味
col, row必須マスの位置
type矢印を付けるなら必須'dash' か 'step'
dir矢印を付けるなら必須矢印の向き
steps任意step で動くマスの数
purpleBorder任意必ずブロックを置くマスにする
gimmicks 必須 配列（マスのリスト）
一言で: 矢印マスや、必ず置くマスのリストです。使わない場合は gimmicks: []。
gimmicks: [
    { col: 1, row: 3, type: 'dash', dir: 'right', purpleBorder: true },
    { col: 3, row: 1, type: 'step', dir: 'left', steps: 1 }
]
type: 'dash' 文字列
一言で: 水色の矢印。ここに置いたブロックが、矢印の向きに端まで滑ります。
途中に別の矢印マスがあると、そこで動き方が変わることがあります。
{ col: 0, row: 2, type: 'dash', dir: 'right' }
左端のマスに置くと、右へ滑ります。
type: 'step' 文字列
一言で: 緑の矢印。ここに置いたブロックが、矢印の向きに決まったマス数だけ動きます。
マス数は steps で決め、書かなければ 1 マスです。
{ col: 2, row: 2, type: 'step', dir: 'up' }
置いたブロックが上に1マス動きます。
dir 文字列
一言で: 矢印の向きです。
値: 'up'（上）、'down'（下）、'left'（左）、'right'（右）の4つだけ。
よくある間違い: 'rigth' のような綴りミスや、大文字の 'Right' は認識されません。
steps 任意 数値
一言で: type: 'step' のときに動くマスの数です。
省略時: 1 マスとして扱われます。既存のステージはすべて steps: 1 です。
'dash' では使われません。
purpleBorder 任意 真偽値
一言で: 紫の枠が付き、「このマスに必ずブロックを置かないとスタートできない」マスになります。
矢印を付けない紫枠: type と dir を省略して { col: 1, row: 2, purpleBorder: true } と書くと、矢印のない「必ず置くマス」になります。実際にステージ3・6・8・11・12で使われています。
紫の枠のマス。ここにブロックを置かないとスタートできません。

5. 仕上げの項目

solution 必須 配列（マスの位置のリスト）
一言で: そのステージの「正解の置き方」です。
何に使われる？ ゲーム画面の電球ボタン（答え合わせ）を押したときに、正解のマスをオレンジ色の枠で表示するために使われます。置いたブロックとの一致数も、これをもとに数えます。
作り方: 先にステージを作り、ゲーム画面で自分で解きます。クリアできたときのブロックの位置を、そのまま書き写します。
確認のポイント: 書いた数が maxBlocks 以下になっているか確認してください。
solution: [
    { col: 3, row: 1 },
    { col: 1, row: 2 }
]
legends 必須 配列（説明書きのリスト）
一言で: 画面の右側に出る「マスの見方」の説明（凡例）です。
1行分の書き方:
{ icon: '▢', type: 'purple', text: '紫枠：必ずブロックを設置' }
  • icon: 先頭に出す記号（文字列）
  • type: 記号の色づけ。'forbidden'（赤）、'dash'（水色）、'step'（緑）、'purple'（紫）のどれか
  • text: 説明の文章（文字列）
ポイント: そのステージで使う種類だけ書けば十分です。text の中の日本語や全角の「：」は、文字列の中なので書いて大丈夫です。
注意: 項目ごと消すとステージ表示でエラーになるため、使わないときも legends: [] と書いてください。

6. よくあるエラーと直し方

ライブエディタ上部の赤いバーに出るメッセージと、その直し方です。バーの「該当行へ移動」を押すと、その行に飛べます。

エディタの表示原因直し方
波括弧「 { 」の位置が不正か、直前の行末尾にカンマ「 , 」が抜けています ステージ同士や項目の間のカンマ忘れ 直前の } や ] の後ろに , を付ける
カンマ「 , 」が抜けているか、文字列が「 " " 」で囲まれていません 項目の間のカンマ忘れ、または引用符の付け忘れ 前の行末にカンマを付ける。文字列は ' で囲む
全角コロン／全角カンマ／全角スペースが含まれています 文字列の外に全角の記号が混ざった 半角に直す。日本語入力をオフにして入力する
コードが途中で終わっています { } や [ ] の閉じ忘れ 開いた数と閉じた数が同じか確認する
エディタが「エラーなし」でも、dir の綴りミスや type の書き間違いは検出されません。矢印が動かないときは、この辞書の綴りと見比べてください。

設計思想と技術スタック

本システムは、ブラウザ標準の HTML5 Canvas、Vanilla JavaScript、Vanilla CSS のみで構築されています。
フレームワーク非依存であるため、ブラウザで開くだけで即座に動作し、DOM操作・描画ループ・状態管理・配列アルゴリズムといったWeb技術の本質を直接学習できる構造になっています。

4つのファイルの役割と連携

ファイル名 レイヤー 役割
stages.js データ層 (Model) ロジックを持たない純粋なデータ定義。全19ステージの初期状態、ギミック、解法配置を保持します。
main.js エンジン (Controller) Canvas描画パイプライン、ブロック連鎖移動シミュレーション、経路走査、アニメーション制御を担当します。
index.html 画面構造 (View) Canvas要素（800x450）、UIコントロール、モーダルダイアログを定義します。
style.css 装飾 (Presentation) レトロデザイン、立体押しボタンのシャドウ表現、レスポンシブ配置を制御します。

状態遷移（ライフサイクル）

変数 phase による状態管理を行っています。

フェーズ 内容 次の遷移
'place' ブロック配置中（プレイヤーが自由に設置・削除可能） スタートボタン押下
'block_move' ギミックによるブロックのスライド移動アニメーション中 全ブロックの移動完了
'running' キャラクターが土管から出発し、ブロック上を走査中 ゴール到達 / 落下 / 激突
'clear' クリア演出（花火・メッセージ） 次ステージ / リセット
'gameover' ミス演出（放物線リスポーン）後に自動復旧 自動で 'place' へ復帰

既存ソースコード完全解説

各ファイルの実装内容を、実際の行番号とともに解説します。ボタンを押すと右側のエディタが該当行へ自動移動します。

1. stages.js のコード構造

全ステージの定義データ配列 STAGES の構造です。

2. main.js の重要ロジック解説

① 連結判定アルゴリズム (checkConnected)

複数ブロックが置かれた際、上下左右斜め（8方向）にすべて連結しているかを深さ優先探索（DFS）で検証します。

main.js (連結チェック関数) 
// main.js: 8近傍DFS探索
function checkConnected() {
    const blocks = [];
    for (let r = 0; r < ROWS; r++) {
        for (let c = 0; c < COLS; c++) {
            if (grid[r][c]) blocks.push({ c, r });
        }
    }
    if (blocks.length <= 1) return true;

    const visited = new Set();
    function dfs(c, r) {
        const key = `${c},${r}`;
        if (visited.has(key)) return;
        visited.add(key);
        // 上下左右斜めの8近傍を再帰探索
        for (let dr = -1; dr <= 1; dr++) {
            for (let dc = -1; dc <= 1; dc++) {
                if (dr === 0 && dc === 0) continue;
                const nc = c + dc, nr = r + dr;
                if (nc >= 0 && nc < COLS && nr >= 0 && nr < ROWS && grid[nr][nc]) {
                    dfs(nc, nr);
                }
            }
        }
    }
    dfs(blocks[0].c, blocks[0].r);
    return visited.size === blocks.length;
}

② 毎フレーム描画ループ (render)

奥の背景から手前のUIへと順番にCanvasへレイヤー描画します。

③ キャラクタールート走査 (solveRoute)

キャラクターが1列進むごとに「正面にブロックがあるか」「足元に足場があるか」「落下するか」をシミュレートし、アニメーション用のキーフレームを生成します。

ギミックの連鎖移動ロジック

複数ブロックの同時移動時、進行方向に応じた優先ソートを行うことで、前方のブロックから順に衝突なく移動させます。また、無限循環移動ギミックに対しては訪問履歴Setによるループ検知で安全に停止します。

歩行・ジャンプ判定仕様

条件 判定式 結果動作
正面にブロック（1段） getBlock(col, curY) 上へジャンプ。ただし頭上（curY-1）にブロックがあれば衝突ミス。
足元に足場あり getBlock(col, curY + 1) 同じ高さを維持して水平歩行。
足場なし 足元ブロックなし 下方のブロックを探して着地。1つもなければ奈落落下でミス。
ゴール列到達 col === 5 ゴールと同じ高さ、または1マス下からの登りジャンプでクリア。

オリジナルステージ作成のステップ

ステージの作成は、パズル作家（レベルデザイナー）のお仕事です！
以下の5つのステップに従うだけで、誰でも面白いオリジナルステージが完成します。

STEP 1
スタートとゴールの高さを決める

startRow（出発土管の高さ）と goalRow（ゴールの高さ）を 0〜4 の数字で決めます。
例: 下から出発して上を目指すなら startRow: 4, goalRow: 0

STEP 2
ブロック上限（maxBlocks）を決める

プレイヤーに何個のブロックを渡すか決めます（5〜7個が標準的）。
少なすぎるとゴールに届かず、多すぎると適当に置くだけでクリアできてしまうので、正解ルートに必要な最小個数ぴったりにするのがコツです。

STEP 3
赤の斜線（forbidden）で邪魔な壁を置く

まっすぐ歩くだけでクリアできないように、forbidden: [ { col: 2, row: 1 }, ... ] でブロックを置けない邪魔なマスを配置します。

STEP 4
矢印ギミック（gimmicks）で動く仕掛けを作る

水色矢印（type: 'dash': 端まで滑る）や緑色矢印（type: 'step': 1マス動く）を配置します。
purpleBorder: true をつければ、必ずブロックを置かないと出発できない必須マスにできます。

STEP 5
正解配置（solution）を登録する

ヒントボタンを押したときに光る「お手本の置き方」を solution: [ { col: 1, row: 3 }, ... ] に登録します。

新ステージ定義のテンプレート

stages.js の配列末尾に追加して作成します。右側のエディタで直接編集・テストが可能です。

新規ステージ用テンプレート (コピペ用) 
    {
        id: 20,                          // ステージ番号 (前の番号の続き)
        title: 'ステージ 20',             // ステージ名
        subtitle: '連鎖移動の応用',        // サブタイトル（ヒント）
        maxBlocks: 6,                    // 最大ブロック数
        startRow: 3,                     // スタート土管の行 (0〜4)
        goalRow: 1,                      // ゴールブロックの行 (0〜4)
        hasCeiling: false,               // 最上部の天井バー有無 (true/false)

        forbidden: [                     // 置いてはいけない赤斜線マス
            { col: 1, row: 0 }, { col: 3, row: 2 }
        ],
        gimmicks: [                      // 矢印ギミックマス
            { col: 1, row: 3, type: 'dash', dir: 'right', purpleBorder: true },
            { col: 3, row: 1, type: 'step', dir: 'left', steps: 1 }
        ],
        solution: [                      // 正解配置（ヒント用のお手本）
            { col: 1, row: 3 }, { col: 2, row: 2 }, { col: 3, row: 1 }
        ]
    },
注意: 初心者がよくハマる2大ミス
  1. カンマ忘れ: 各行の末尾に ,（カンマ）を付け忘れると、エディタが赤くエラー表示になり反映できません。
  2. ブロックの孤立: ハコゲームには「置いたブロックは必ず縦横斜めで繋がっていなければならない」という連結ルールがあります。離れ小島のようなブロックを置くパズルはスタートできないので注意しましょう！

クリアできない時のチェックリスト

主な失敗原因
  • 1. 1列目の足場不足: スタート土管直前（列0）に足場がないと即落下します。
  • 2. 頭上衝突: 1段ブロックを登る際、真上のマスにブロックがあると激突します。
  • 3. ゴール高さ不一致: ゴール位置（goalRow）と同じ高さ、または1マス下からの進入でなければ壁衝突になります。
